# CareerSphere 采集方案

## 目标

为现有职业游戏提供可追溯的马来西亚招聘广告样本、职业分布、技能提及率和周趋势。第一版先接招聘 API，再补充已经核实的动态网页来源。

## 架构

n8n 定时创建任务 → Node.js 独立采集服务 → JSearch 或 Playwright 适配器 → 归一化/去重/技能提取 → SQLite 原始记录及不可变观察版本 → 统计 JSON → 现有 Node.js 后端 → 游戏热力图和排行。

n8n 不运行长浏览器任务；前端不直接抓网页，也不持有服务凭据。

## 已实现模块

| 模块 | 文件 | 用途 |
|---|---|---|
| 配置 | config/market.json | 职业查询、技能词典、来源、预算 |
| API | src/sources/jsearch.js | v2 schema、cursor、提供商认证 |
| 浏览器 | src/sources/browser.js | JS、分页、滚动、详情页 |
| 清洗 | src/normalize.js | 国家核实、职业映射、技能及依据 |
| 存储 | src/store.js | 原始记录、去重、历史版本、运行锁 |
| 统计 | src/analytics.js | 当前快照、技能率、周窗口比较 |
| 调用 | src/server.js | 异步 202、鉴权、状态接口 |
| 命令 | src/cli.js | demo/crawl/summary/export/push/serve |
| 调度 | n8n/daily-crawl.json | MYT 08:00 启动模板 |

## 默认范围

3 个技术职业、每个最多 2 页，单次 12 次 API 请求尝试（包含重试），间隔 1.5 秒，10 分钟总时限，最多 1000 行。根据配额和返回质量调整。该范围不足以发现整个市场所有新职业，后续可添加经审查的广泛查询，变更范围后重新建立同口径历史。

## 数据设计

runs 保存 scope、时间、租约和结果；jobs 保存内部身份及首次/最近观察；job_sources 关联多个来源；revisions 保存字段和技能的版本；observations 关联某次运行与版本；raw_records 保存当次来源原始内容；tasks 保存每次查询状态。

同运行同来源职位重复时 raw_records 保留最后一份。国家不明的拒绝记录只计原因，不持久保存完整拒绝原文。

去重先查来源 ID，再保守使用相同链接及相同公司/标题/地点/描述，最后查公司/标题/地点/描述完全相同指纹。没有稳定 ID 的回退身份受标题和链接变化影响；不自动模糊合并。

## 动态页面处理

等待明确 ready/empty 条件；先登记分页响应监听再操作；逐批保存 ID，支持虚拟列表；需要时进入详情页；通过结束标记、按钮不可用、分页步数、预算和时间停止。停滞或故障不能推断市场没有职位。实际来源需填写并验证选择器，默认模板禁用。

## 质量与趋势

健康状态 complete/capped；不完整为 partial/failed/interrupted。全局预算中断与页面故障不会被当成健康零样本。固定预算成功运行的 capped 仍是部分样本。

技能词典仅识别提及，保留证据，不自动判定必备程度。周趋势的分子、分母按同 scope 的两个完整七天窗口中的不同观察广告计算；每一天都需健康运行。历史不足时返回 null，不补造历史，上期零时不算百分比。

## 接入与部署

服务默认只监听回环地址，支持 Bearer 鉴权。现有后端使用 GET summary 或适配导出契约后接收 push；不能猜测接收路由。推送按 runId 幂等，不自动重试未知接收端 POST。

n8n 模板只启动，不把 202 当成功；通过 statusUrl 查询结果。后续按真实需要增加告警、多个来源或外部数据库，不先增加分布式组件。

## 剩余实际配置

真实采集需要用户自己的 API Key/配额；动态采集需要目标网址和实际选择器；现有游戏集成需要本地代码和真实接口契约。当前交付独立项目，未修改用户电脑或线上服务。
